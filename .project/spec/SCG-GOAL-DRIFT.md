# SCG-GOAL-DRIFT — สัญญาป้องกัน AI เปลี่ยนเป้าหมาย

## WHAT — ระบบต้องทำอะไร

1. ทุกโปรเจกต์มีใบงานปัจจุบันที่เครื่องอ่านได้เพียงชุดเดียว และมุมมองสำหรับคนต้องสร้างจากใบงานนั้น
2. ใบงานต้องผูก `task_id`, `plan_id`, เป้าหมาย, ผลที่ต้องส่ง, กิ่ง, SHA ฐาน, เส้นทางที่อนุญาต/ห้าม, ชนิดงาน, หลักฐานอนุมัติ, สถานะ และลายนิ้วมือเป้าหมาย
3. คำว่า “อนุมัติ” ทั่วไปเปลี่ยนขอบเขตไม่ได้ การเปลี่ยนต้องระบุงานเดิม งานใหม่ กิ่ง เส้นทาง และผลกระทบ
4. โปรเจกต์ที่พบปัญหามีสิทธิ์รายงานเหตุ แต่ไม่มีสิทธิ์แก้ Prompt, Shortcut, Hook หรือด่านกลาง
5. ใช้กติกาเดียวกันก่อนเขียน ก่อน commit ก่อน push ใน CI และก่อน merge
6. กิ่งที่รวมแล้วมีสถานะ frozen และรับงานใหม่ไม่ได้จนมีใบงานใหม่
7. New Chat และ Close Chat ต้องเทียบความหมายกับใบงาน ไม่ใช่ตรวจเพียงว่าไฟล์ถูกเขียนพร้อมกัน
8. Use Agent เป็นคำสั่งเข้าหลักและต้องบอก Prompt ถัดไป หรือบอกว่า AI ทำต่อเองโดยเจ้าของไม่ต้องพิมพ์อะไร
9. เปอร์เซ็นต์ของผลงานหลักแยกจากงานสนับสนุน เช่น Hook เอกสาร และเครื่องมือตรวจ
10. งานปลอดภัยเดินต่อทั้ง Phase โดยไม่ให้เจ้าของพิมพ์เลขเฟสย่อย เว้นแต่เจ้าของขอโหมดควบคุมด้วยมือ

## WHY — เหตุผล

- เหตุ Design System แสดงว่างานนอกขอบเขต 44 ไฟล์ถูก merge เพราะความจำผิดถูกกระจายเป็นข้อมูลที่ดูสอดคล้องกัน
- เหตุ Fable/500k แสดงว่างานแก้ Hook และแผนแทรกงานหน้าจอ และภาพที่มีไฟล์ครบไม่ได้แปลว่าตรงแบบ
- การเพิ่มข้อความเตือนเพียงอย่างเดียวเคยล้มเหลวแล้ว จึงต้องมีด่านที่ผิดแล้วหยุดก่อนเกิดความเสียหาย

## ขอบเขตในงาน

- Use Agent, Use Act-As, Use Comply, Use New Chat, Use Continue
- Use Flow Guardian, Use Save Git, Use Close Chat/Use Post Chat
- Use Create Design System, Use Migrate Web และ Use QA QC
- ตัวติดตามเหตุ Shortcut กลาง, ใบงานปัจจุบัน, ด่านก่อนเขียนและด่าน Git
- ชุดติดตั้งทีมและการตรวจ Mac/VPS/เครื่องทีม

## นอกขอบเขต

- คืนโค้ดของ MR !78 หรือแก้โปรเจกต์ Design System/Fable โดยตรง
- เปลี่ยนระบบ production ของโปรเจกต์ต้นเหตุ
- สร้างหรือสลับ Worktree/กิ่ง
- แก้ Prompt/Shortcut จากโปรเจกต์ที่พบเหตุ
- เพิ่มแหล่งสถานะถาวรอีกชุดที่ต้องกรอกด้วยมือ

## ชุดทำซ้ำบังคับ

### เหตุ Design System 10/10

งานสีและฟอนต์ที่อนุญาตต้องผ่าน 2/2; seed, API/DB, temp content, RoadSafeFund, TipTap, staging/runtime, Close Chat เพิ่ม P2-P5 และ commit หลัง frozen ต้องถูกปฏิเสธ 8/8

### เหตุ Fable/500k 8/8

1. แผน active ชนะเอกสารเก่า
2. สิทธิ์ทำหน้าจอไม่ให้สิทธิ์แก้ Hook/audit/flow
3. งานสนับสนุนไม่นับเป็นเปอร์เซ็นต์หน้าจอ
4. URL และ CSS ต้องตอบถูกก่อนถ่ายภาพ
5. มีภาพแต่ไม่ตรงแบบต้องตก
6. ข้อมูลไม่ครบต้องรักษาโครงตามแบบและบอกข้อมูลที่ขาด
7. build ห้ามชนกับ server ที่ใช้เก็บภาพ
8. Close/New Chat ต้องรักษาหน้าปัจจุบันและงานถัดไปหนึ่งข้อ
