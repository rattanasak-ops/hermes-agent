# Use Migrate 4 — เขียนโจทย์ก่อนแตะโค้ด (สถานี M2 · Design Brief 9 หัวข้อ)

> ก่อนเขียนโค้ดแม้แต่บรรทัดเดียว ต้องมีโจทย์ครบ 9 หัวข้อ + 3 ช่องบังคับ · ขาด = โจทย์ตก เข้าเฟสถัดไปไม่ได้

## Prompt

```text
Use Migrate 4

อ่านสัญญากลาง use-migrate-phase-contract.md ก่อน แล้วทำตามโครง 5 ส่วน

[ส่วน 1 · ด่านเข้า — รันจริง แปะผล]
1. .work/profile.yaml มีจริง — ไม่มี = MIGRATE_BLOCKED: ต้องทำ Use Migrate 0 ก่อน
2. ล็อกเมนูยังเป็นชื่อเรา + บัตรเมนู (confirm เฟส 1) + ผลเฟส 2 (NO_INPUT/benchmark) + ของเฟส 3 (harvest/audit/parity ตามโหมด) มีจริงครบ — ขาด = BLOCKED บอกเฟสที่ค้าง
- ประกาศสถานี: [Migrate เฟส 4/13 · สถานี M2 · เมนู: <ชื่อ> · โปรเจกต์: <ชื่อ>]

[เนื้องาน — โจทย์ 9 หัวข้อ เขียนลง .work/menu-cards/<เมนู>.brief.md]
M2-1 การใช้งานระดับหน้า (Page Journey): ใครเข้าหน้านี้ · มาทำอะไร · ก่อน-ระหว่าง-หลังเจออะไร · วัดสำเร็จ (เช่น หาแบบฟอร์ม ≤3 คลิก)
     — Journey ระดับเว็บจบไปแล้วใน strategy master · ขั้นนี้คือระดับหน้าเท่านั้น · ถ้าพบว่าขัดกับ Sitemap ที่อนุมัติแล้ว → หยุด ถามเจ้าของ ห้ามแก้ Sitemap เอง
M2-2 ของเก่ามีปัญหาอะไร (อ้างไฟล์วิเคราะห์เก่า + ภาพจากเฟส 3): เนื้อเป็น JPG อ่านไม่ได้ / ไม่รองรับมือถือ / ลิงก์ตาย
M2-3 ไอเดียใหม่ที่เพิ่ม: แก้ปัญหาเก่ายังไง + เพิ่มคุณค่าอะไร + WOW ยังไง เพราะอะไร
M2-4 วิธีนำเสนอ (Treatment) ตอบทีละข้อ: อินโฟกราฟิก? · หน้าโต้ตอบได้? · ตัวเลขนับ? · ตาราง+ตัวกรอง? · stepper?
M2-5 ภาพประกอบ: ต้องมีภาพอะไร · ที่มา = harvest เก่า/ขอลูกค้า/stock ลิขสิทธิ์เท่านั้น (ห้าม AI สร้างภาพคน)
M2-6 จุดว้าว = ผู้ใช้ทำสำเร็จ ไม่ใช่ดีไซน์เด่น: ระบุ KPI ปิดเมนู + หน้าให้คำแนะนำสิทธิ์ต้องมีข้อความกันความเสี่ยง
M2-7 WOW METHOD 6 มุมมอง: คนใช้จริง · กรณีขอบ · เกณฑ์ราชการ→จุดเด่น · ทางเลือก+รู้ผล · เห็นผลก่อนบันทึก · เกินคาด 1 อย่าง
M2-8 ผูกมาตรฐาน: TOR ข้อไหน · ภาครัฐ 3.0/ITA ข้อไหน + อ้าง REQ ID จริงจาก .work/req-register.md (ห้ามอ้างลอย)
M2-9 Dignity/โทน (กลุ่มผู้พิการ): ห้ามโทนสงสาร → "คุณมีสิทธิ ทำได้เอง" · ห้ามภาพเหมารวม · ภาษาเคารพ

3 ช่องบังคับ (ขาดข้อใด = โจทย์ตก): จุดอ่อนเก่า ≥1 / Emotion เป้าหมายของหน้า / จุดว้าว+วิธีวัด
เสริมบังคับ: หน้ายาว >2 A4 → วางแผนภาพคั่นสายตาทุกช่วง A4 (magazine layout ซ้าย→ขวา บน→ล่าง) ·
ถ้าจะใช้วิดีโอพื้นหลัง → เขียนเหตุผลความเหมาะต่อหน้า (≤2MB · ไม่เปิดเสียงเอง · ปุ่มหยุด · เคารพ reduced-motion) ·
เจออินโฟกราฟิก/ไดอะแกรมเก่าไม่สวย → เสนอทำใหม่ใน brief ให้เจ้าของ confirm (ลงมือจริงเฟส 6)

[ส่วน 4 · ชุดคำถามบังคับ — รอบเดียว แล้วหยุดรอ]
ส่งร่างโจทย์ครบ 9 หัวข้อ แล้วถาม:
1. จุดว้าว + วิธีวัด ที่เสนอ — เอาไหม ปรับตรงไหน?
2. Treatment ที่เลือก (แท็บ/อินโฟกราฟิก/ตาราง...) — ใช่ทางที่พี่ต้องการไหม?
3. รายการอินโฟกราฟิก/ไดอะแกรมที่เสนอทำใหม่ — เอาข้อไหนบ้าง?
→ คำตอบจดลง brief · เจ้าของยังไม่ตอบ = โจทย์ยังไม่ปิด

[ส่วน 5 · ตารางจบเฟส]
(ก) ของส่งมอบ: .work/menu-cards/<เมนู>.brief.md (9 หัวข้อ + 3 ช่องบังคับ + คำตอบเจ้าของ) — พิสูจน์ ls + git ls-files + wc -l
(ข) ตาราง comply M2-1..M2-9 + 3 ช่องบังคับ = 12 แถว + หลักฐาน
(ค) เลขจากเครื่อง: flow_gate.py ถ้ามี · ไม่มี = ระบุ "เครื่องยังไม่คุม"
ปิดท้าย: จบเฟส 4 — รอพี่ตรวจ · ถ้าผ่าน พิมพ์ `Use Migrate 5` · ผมเดินต่อเองไม่ได้ (กุญแจอยู่ที่พี่)

[ข้อห้ามเฉพาะเฟสนี้]
- ห้ามค้นภาพจริง (เฟส 5-6) ห้ามออกแบบลูกเล่น (เฟส 7) ห้ามแตะโค้ด (เฟส 8)
```
