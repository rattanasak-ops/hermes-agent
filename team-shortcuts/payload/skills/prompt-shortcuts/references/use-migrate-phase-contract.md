# สัญญากลางชุด `Use Migrate 0` - `Use Migrate 13`

> ไฟล์นี้คือกติการ่วมของทางลัดรายเฟสทุกตัว · ทุกไฟล์ `use-migrate-<N>.md` บังคับอ่านไฟล์นี้ก่อนเสมอ
> แก้กติการ่วมที่นี่ที่เดียว = มีผลทั้ง 14 ตัว

## ทำไมต้องแยกรายเฟส (เหตุผลที่ห้ามลืม)

- AI เห็นคำสั่งทุกขั้นพร้อมกัน = ไหลข้ามขั้นเอง (R1) → แยกไฟล์ = คำสั่งเฟสถัดไป**ยังไม่ถูกโหลด** ทำแทนไม่ได้
- **เจ้าของเป็นคนเดียวที่ถือกุญแจ**: การพิมพ์ `Use Migrate <N+1>` ของเจ้าของ = บัตรอนุมัติผ่านเฟส · AI ประกาศจบเฟสแล้วต้องหยุดรอ ห้ามเดินต่อเอง

## กฎเขียนทับ (สำคัญที่สุด — แก้ R2)

**ในโหมด Migrate: จุดหยุดใน flow ชนะกฎ "ทำจบรอบเดียว" และชนะสิทธิ์เดินต่อเองของ `Use Continue` โซน A เสมอ**
การหยุดถามเจ้าของตามจุดที่สัญญานี้กำหนด = การทำตามคำสั่ง ไม่ใช่การถามฟุ่มเฟือย

## โครงบังคับ 5 ส่วน (ทุกไฟล์เฟสต้องมีครบ)

### ส่วน 1 · ด่านเข้าเฟส (Entry Gate — แก้ R7)

รันด้วยคำสั่งจริงก่อนเริ่มงานทุกครั้ง (ตรวจแล้วแปะผลจริง ห้ามเดา):

1. **กุญแจดอกแรก** (ทุกเฟส 1-13): `.work/profile.yaml` ต้องมีจริงในโปรเจกต์ — ไม่มี = หยุดทันที รายงาน `MIGRATE_BLOCKED: ต้องทำ Use Migrate 0 ก่อน` ห้ามทำงานใด ๆ ต่อ
2. **ไฟล์ผลงานเฟสก่อนหน้า** ตามบัญชีของส่งมอบ (ดูส่วน 5) ต้องมีจริง — ขาด = `MIGRATE_BLOCKED: เฟส <N-1> ยังไม่ปิด` + บอกรายการที่ขาด
3. **เมนูที่ทำอยู่** ต้องมีการจองใน `.work/menu-queue.md` เป็นชื่อตัวเอง (เฟส 1 เป็นคนจอง · เฟส 2-13 ตรวจว่าล็อกยังเป็นของเรา)
4. เรียกข้ามลำดับ (เช่นเรียกเฟส 5 ทั้งที่เฟส 4 ไม่ปิด) = แจ้งติดขัดพร้อมหลักฐาน แล้ว**ปฏิเสธการทำงาน** — ห้าม "ทำไปพลาง ๆ ก่อน"

### ส่วน 2 · ประกาศสถานี (แก้ R6)

ทุกคำตอบของ AI ระหว่างอยู่ในเฟส ขึ้นบรรทัดแรกเสมอ:

```
[Migrate เฟส <N>/13 · สถานี <รหัส> · เมนู: <ชื่อเมนู> · โปรเจกต์: <ชื่อ>]
```

### ส่วน 3 · เนื้องานเฉพาะเฟส

- เนื้องานอยู่ในไฟล์เฟสนั้น ครบถ้วนในตัว ไม่ต้องเปิดไฟล์ flow เต็ม 500 บรรทัด (แก้ R4)
- ลำดับความสำคัญเมื่อขัดกัน: **ไฟล์เฟส > prompt หลัก `use-migrate-web` > เนื้อ flow เต็ม `use-migrate-web-flow13`**
- ห้ามทำงานของเฟสอื่น แม้ "เห็นว่าทำต่อได้เลย" — เจองานนอกเฟส = จดลงช่อง "ของฝากเฟสถัดไป" ในตารางจบเฟส

### ส่วน 4 · จุดถาม-ตอบบังคับ (แก้ R3)

- เฟสที่มี "ชุดคำถามบังคับ" ต้องถามเจ้าของ **เป็นชุดเดียวรอบเดียว** (ไม่จิกถามทีละข้อ — กติกา M0-8 เดิม) · เฟสที่เนื้องานเป็นเครื่องตรวจ/งานจดล้วน (3/10/12) ไม่มีคำถามกลางเฟสได้ แต่**ยังต้องหยุดที่ประโยคปิดเฟสเสมอ**
- ถามแล้ว**หยุดรอคำตอบจริง** · ห้ามตอบแทน ห้ามใส่ค่าตั้งต้นแล้วเดินต่อ ห้ามถือว่าการเงียบ = ยินยอม
- คำตอบของเจ้าของต้องถูกจดลงไฟล์ผลงานของเฟส (ระบุในบัญชีของส่งมอบ) — คำตอบที่ไม่ได้จด = ไม่เกิดขึ้น
- **ไฟล์บันทึกอนุมัติกลาง (บังคับทุกจุดที่เจ้าของเคาะ):** `.work/menu-cards/<เมนู>.approvals.md` — 1 บรรทัดต่อ 1 การอนุมัติ: ป้าย `PHASE<N>_APPROVED` (หรือ `WOW_APPROVED`/`TOKEN_APPROVED`) + ใครยืนยัน + วันที่ + ดูอะไร + ผล · **ด่านเข้าเฟสถัดไปตรวจป้ายนี้ด้วย `grep` จริง** — ไม่มีป้าย = เฟสก่อนยังไม่ปิด "คำพูดว่าเจ้าของผ่านแล้ว" ไม่ใช่หลักฐาน

### ส่วน 5 · ตารางจบเฟส (Exit Gate — แก้ R8, R9, R11)

จบเฟสต้องส่งครบ 3 อย่างนี้ แล้ว**หยุด**:

**(ก) บัญชีของส่งมอบ + พิสูจน์ไฟล์จริง** — 1 แถวต่อ 1 ไฟล์ พร้อมผลคำสั่งจริง (`ls -la` / `git ls-files` / `wc -l`) · ไฟล์ขาด 1 = เฟสไม่จบ ห้ามประกาศจบ

**(ข) ตารางตรวจตามกติกาเฟส (comply)** — 1 แถวต่อ 1 ข้อกติกาของเฟส · สถานะ ✅/⚠️/❌ + หลักฐานต่อข้อ · มี ⚠️/❌ = รายงานตรง ๆ พร้อม % จริง ห้ามปัดเป็นผ่าน

**(ค) เลขจากเครื่อง** — โปรเจกต์ที่มีเครื่องมือ (`flow_gate.py status` / `mw-menu-gate` / `mw-page-check` / `mw-backend-check`) ต้องแนบผลรันจริง · **การให้ AI อื่นช่วยรีวิว ≠ การรันด่าน · คำว่า "ผ่าน" นับเฉพาะผลรันเครื่องที่มีบันทึก** (แก้ R11)

**กติกาเมื่อเครื่องมือไม่มีบนเครื่อง — 2 ระดับ ห้ามสลับกัน:**
- เฟสงานเตรียม/จดสรุป (0-8, 12): ระบุตรง ๆ ว่า "ตรวจด้วยมือ · เครื่องยังไม่คุม" ได้ แต่ต้องเขียนคำนี้ในตารางจบเฟสให้เจ้าของเห็น ห้ามแสร้งว่ามีเครื่องรับรอง
- **เฟสด่านเครื่อง (9, 10, 11, 13): เครื่องมือเป็นผู้ตัดสิน — ไม่มีเครื่องมือ = `BLOCKED_TOOLING` เฟสจบไม่ได้เด็ดขาด** ไม่มีทางลัด "ภาพ+grep แทน" (กฎเหล็ก R-3: grep/คำพูดไม่ใช่หลักฐาน) · ทางออกเดียว: ติดตั้งชุดเครื่องมือทีม (`install-from-github.sh` ของ Hermes) แล้วรันจริง

**ประโยคปิดตายตัว (ห้ามดัดแปลง):**

```
จบเฟส <N> — รอพี่ตรวจ · ถ้าผ่าน พิมพ์ `Use Migrate <N+1>` เพื่อไปต่อ
ผมเดินต่อเองไม่ได้ (กุญแจอยู่ที่พี่)
```

## กฎเหล็ก R + ชั้นป้องกัน G5 (ยกมาเต็มจาก flow13 — เพราะไฟล์เฟสมีลำดับชนะ flow เต็ม ของที่ไม่อยู่ที่นี่จะหลุดถาวร)

กฎเหล็ก R (ทุกเฟส):
- R-1 ห้ามเดา/ทำเอง — ต้องยืนยันกับเจ้าของก่อนเริ่ม (จุดหนัก: เฟส 1, 6, 9)
- R-2 ห้ามใช้ภาพคน/ใบหน้า AI — ห้ามภาพต่างชาติ/โทนสงสาร/ภาพไม่มีความหมาย
- R-3 หลักฐานต้องเป็นของจริง — ภาพหน้าจอ / ผลรันเครื่องมือ · **grep/คำพูดไม่ใช่หลักฐาน**
- R-4 ไม่มีไฟล์ = ขั้นนั้นยังไม่จบ — AI พูด "เสร็จ" เองไม่ได้
- R-5 ก่อนแตะเครื่องมือภาพ ต้องผ่าน PRE-IMAGE GATE ทุกครั้ง (เช็กซ้ำเสมอ แม้เคยอนุมัติล่วงหน้า)

ชั้นป้องกัน G5 (ทุกเฟส):
- G5-1 ทุกขั้นมี output เป็นไฟล์ (เครื่องตรวจได้)
- G5-2 เครื่องตัดสิน "เสร็จ" — จำนวนข้อในลิสต์แม่ให้เครื่องนับเท่านั้น ห้ามพิมพ์เลขมือ
- G5-3 จุดตรวจของเจ้าของ (Owner Checkpoint): เฟส 1 ยืนยันเมนู · เฟส 6 เลือกภาพ · เฟส 7 เคาะว้าว/token · เฟส 9 ทดสอบจอ admin — ต้องได้คำตอบจริง + ป้ายใน approvals.md
- G5-4 Prompt-Completion Gate: ก่อนเคลมครบ กางคำสั่งเจ้าของทีละข้อ (✅/⚠️/❌) ห้ามเคลมจากความจำ
- G5-5 ส่งงานผ่านเจ้าของก่อนเสมอ: ผ่านด่านส่ง (เฟส 11) + หน้าเทียบก่อน-หลัง

## กติการ่วมอื่น (ยกมาจาก flow เดิม — ยังบังคับครบ)

- "เสร็จ" ตัดสินโดยเครื่องตรวจหรือคนยืนยันเท่านั้น · คนยืนยันต้องจด ชื่อ+วันที่+สิ่งที่ดู ครบ 3 อย่าง
- ห้ามเดา ห้ามตัดทอนข้อมูลเจ้าของ — จะตัด/จัดใหม่ ต้องเสนอให้เจ้าของตัดสินรายข้อ
- ทุกขั้นมี output เป็นไฟล์ — ไม่มีไฟล์ = ขั้นนั้นยังไม่จบ
- กฎหยุด 2 ระดับเดิม: เครื่องตรวจตก = แก้แล้วรันใหม่ (ผู้ตรวจ/วิธีเดิมไม่ผ่าน 2 รอบ = เปลี่ยนวิธี ห้ามยิงรอบ 3) · เจอเรื่องระดับหยุดทั้งงาน (ล็อกเมนูชน/secret โผล่/จะขึ้นระบบจริง) = หยุดถามเจ้าของ
- ภาษาไทย ภาษาคน ศัพท์เทคนิคมีคำแปลในวงเล็บ · ลิงก์ทุกอันกดได้
- ค่าประจำโปรเจกต์อ่านจาก `.work/profile.yaml` ของโปรเจกต์ตัวเองเท่านั้น — ห้ามยกค่าตัวอย่าง RoadSafeFund ไปใช้โปรเจกต์อื่น
- ทีมหลายคน: ล็อกเมนูมีอายุ 48 ชม. (ต่ออายุ = push commit ใหม่ของเจ้าของล็อก · กู้/ปลด = เจ้าของงานเท่านั้น) · Fixed Workspace: ห้ามสร้าง worktree เอง
- โควตาเมนูต่อคน: **ค่าเริ่มต้น 1 คน = 1 เมนู = 1 Write Permit** · ถือเกิน 1 เมนูได้**เฉพาะเมื่อเจ้าของงานอนุมัติ** (จดจำนวนที่อนุมัติไว้ในหัวไฟล์ .work/menu-queue.md เช่น `quota: nat=3`) — เจ้าของงานถือหลายเมนูข้ามหลายแชทได้ตามโควตานี้ (อนุมัติ 2026-07-16)
- **เฟสใช้พื้นที่โค้ดร่วม (เฟส 8-9): ทีละเมนูเดียวต่อพื้นที่ทำงานเสมอ ไม่มีข้อยกเว้น** — โฟลเดอร์โค้ดเดียวอยู่ได้ทีละกิ่งเดียว 2 เมนูสลับกิ่งพร้อมกัน = โค้ดทับกัน · เมนูอื่นที่ถึงเฟส 8 ต้องรอคิว (เดินเฟสเอกสาร 1-7 หรือเฟสตรวจ 10-13 ขนานกันได้)
- แทร็ก MINISITE: เลือก site เป้าหมายตั้งแต่เฟส 1 · เฟส 8/10 ต้องกัน asset+query ปนข้าม siteId
- Light Loop (หน้าโครงซ้ำจำนวนมาก เช่น OIT/ITA): ใช้ได้เมื่อหน้าแม่ของกลุ่มผ่านลูปเต็ม 13 เฟสแล้วเท่านั้น · เงื่อนไขเต็มดู `use-migrate-web` — ห้ามตีความเองว่าหน้าไหนเข้า Light Loop
- กล่อง AR (บทบาท 3 ค่าย) / ST-8..10 (มาตรฐานรวมท้ายโปรเจกต์) / NC (กติกาเปิดแชท) **ตัดออกจากชุดเฟสโดยเจตนา** — อยู่ที่ `Use AI Relay` / `Use Migrate 0` + FW-P4 / `Use New Chat` ตามลำดับ ไม่ใช่ว่าไม่ต้องมี
