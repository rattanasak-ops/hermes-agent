# Use Migrate 3 — เก็บของเก่า (สถานี M1 · ตามโหมดโปรเจกต์)

> หลักการแกน: ข้อมูลเก่า = ของดิบเอามาใช้ได้ · จัดใหม่ให้สวย+เข้าถึงง่าย ไม่ทิ้งของเดิม · ของที่ดึงไม่ได้ต้องมีร่องรอยเป็นใบสั่งงานทีมเสมอ

## Prompt

```text
Use Migrate 3

อ่านสัญญากลาง use-migrate-phase-contract.md ก่อน แล้วทำตามโครง 5 ส่วน

[ส่วน 1 · ด่านเข้า — รันจริง แปะผล]
1. .work/profile.yaml มีจริง — ไม่มี = MIGRATE_BLOCKED: ต้องทำ Use Migrate 0 ก่อน
2. ล็อกเมนูยังเป็นชื่อเรา + บัตรเมนูจากเฟส 1 มีจริง
3. เฟส 2 ปิดจริง: .work/menu-cards/<เมนู>.benchmark.md มี `status: NO_INPUT` หรือ `status: SELECTED` พร้อมคำตอบเจ้าของอ้างได้ (cat แปะเนื้อจริง — ไฟล์ว่าง/ไม่มีคำตอบเจ้าของ = ไม่นับ) — ไม่ผ่าน = BLOCKED กลับเฟส 2
4. อ่านโหมดจาก profile.yaml: MIGRATE / REMEDIATE / BUILD → เลือกรูปขั้นข้างล่างตามโหมด ห้ามเดา
- ประกาศสถานี: [Migrate เฟส 3/13 · สถานี M1(<โหมด>) · เมนู: <ชื่อ> · โปรเจกต์: <ชื่อ>]

[เนื้องานตามโหมด — ทำเฉพาะโหมดของโปรเจกต์]

โหมด MIGRATE (ย้ายเว็บเก่า) — M1-1..M1-6 ครบ:
M1-1 ถ่ายภาพเต็มหน้า (จอคอม + จอมือถือ) → harvest/<เมนู>/old-*.png
M1-2 ดูด HTML/PDF/รูปของหน้านั้น → harvest/<เมนู>/
M1-3 ดึงไม่ได้ (ลิงก์ตาย/Google Drive/ต้องล็อกอิน) → จดลง .work/MANUAL-TODO.md = ใบสั่งงานทีมคน ทันที:
     ไฟล์อะไร · URL ไหน · ทำไมดึงไม่ได้ · ใครควรทำ · วิธีทำ — AI ปิดแทนไม่ได้
M1-3b สร้างหน้ารวมภาพ (gallery HTML) ของที่เก็บมา + ของที่ดึงไม่ได้ ให้ทีมกดดูผ่านลิงก์ได้
M1-4 จดข้อสังเกต: ภาพ/ข้อมูลเก่าที่มีปัญหา จะเสนอทำใหม่เป็น Diagram/Infographic (ไปตัดสินที่เฟส 4-5)
     + ถามเจ้าของเรื่อง related content (กัน killer page) — จดคำตอบลงบัตรเมนู
M1-5 เพิ่มมูลค่าได้ (แท็บ/ค้นหา/ขั้นตอน) แต่ห้ามสร้างภาระให้ลูกค้า
M1-6 เมนูเก่ามีหลายหน้าย่อย → วางแผนจัดเป็นแท็บรวมหน้าเดียว (จดลงบัตรเมนู)

โหมด REMEDIATE (ซ่อมเว็บปัจจุบัน) — M1R:
- audit เว็บปัจจุบันของเมนูนี้: ตรวจ "เนื้อหาจริงที่ควรมี" ใน rendered main content
- ห้ามเชื่อ HTTP 200 (กัน soft-404: หน้าเปิดได้แต่เนื้อว่าง/error ปน) — แปะหลักฐานเนื้อจริง
- ผลตรวจลง harvest/<เมนู>/audit.md + ของเสีย/ขาดเข้า MANUAL-TODO.md เหมือนกัน

โหมด BUILD (สร้างจากฐานข้อมูล) — M1-D:
- inventory + mapping ฐานข้อมูลของเมนูนี้: count parity 100% ทุกตาราง (นับต้นทาง=ปลายทาง)
- spot check สุ่ม seed คงที่ ≥5%/ตาราง (ขั้นต่ำ 20 รายการ) เทียบรายช่อง — ตก ≥1 = ทั้งตารางไม่ผ่าน
- ตรวจเพิ่ม: FK/orphan · ไฟล์ภาพ/แนบครบ · ตัวอักษรไทยไม่เพี้ยน · รายการซ้ำ/เสีย
- มีแผนย้อนกลับก่อนย้ายจริง + ป้อน Data Dictionary

[ส่วน 4 · จุดถาม-ตอบ]
เฟสนี้ส่วนใหญ่ไม่รอเจ้าของ ยกเว้น: คำถาม related content (โหมด MIGRATE) + กรณีของเก่ากำกวม/เข้าไม่ได้ระดับทั้งเมนู = ถามก่อนเดินต่อ

[ส่วน 5 · ตารางจบเฟส]
(ก) ของส่งมอบตามโหมด — พิสูจน์ ls + git ls-files:
  MIGRATE: harvest/<เมนู>/ (ภาพ+ไฟล์) · gallery HTML · MANUAL-TODO (ถ้ามีของดึงไม่ได้)
  REMEDIATE: audit.md + หลักฐานเนื้อจริง · BUILD: ตาราง parity + ผล spot check + แผนย้อนกลับ
(ข) ตาราง comply รายข้อของโหมดที่ใช้ + หลักฐาน (เลขนับจากคำสั่งจริง เช่น ls | wc -l)
(ค) เลขจากเครื่อง: flow_gate.py / mw-page-check ถ้ามี · ไม่มี = ระบุ "เครื่องยังไม่คุม"
ปิดท้าย: จบเฟส 3 — รอพี่ตรวจ · ถ้าผ่าน พิมพ์ `Use Migrate 4` · ผมเดินต่อเองไม่ได้ (กุญแจอยู่ที่พี่)

[ข้อห้ามเฉพาะเฟสนี้]
- ห้ามเขียนโจทย์ดีไซน์ (เฟส 4) ห้ามหาภาพ (เฟส 6) ห้ามแตะโค้ด
- ของดึงไม่ได้ = จดใบสั่งงานทีม ห้ามข้ามเงียบ ห้ามถือว่า "ไม่มี"
```
