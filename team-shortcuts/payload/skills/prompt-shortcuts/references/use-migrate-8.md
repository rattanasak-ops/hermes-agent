# Use Migrate 8 — เขียนหน้าใหม่ = ใช้ Design System เท่านั้น (สถานี M4)

> เฟสแรกที่แตะโค้ด · ใช้เฉพาะ token ที่อนุมัติแล้ว · ห้ามคิดสี/ฟอนต์ใหม่กลางทาง

## Prompt

```text
Use Migrate 8

อ่านสัญญากลาง use-migrate-phase-contract.md ก่อน แล้วทำตามโครง 5 ส่วน

[ส่วน 1 · ด่านเข้า — รันจริง แปะผล]
1. .work/profile.yaml มีจริง — ไม่มี = MIGRATE_BLOCKED: ต้องทำ Use Migrate 0 ก่อน
2. ล็อกเมนูยังเป็นชื่อเรา + ตรวจห่วงโซ่ไฟล์ครบ (grep/ls แปะผลทีละตัว): confirm เฟส 1 (กติกา M0-6) · benchmark.md เฟส 2 · harvest/audit เฟส 3 · brief เฟส 4 · image-direction เฟส 5 · asset-register เฟส 6 · ป้าย `WOW_APPROVED` (+`TOKEN_APPROVED` ถ้ามี) ใน approvals.md เฟส 7 — ขาด = BLOCKED บอกเฟสที่ค้าง
3. เช็กก่อนแก้: dev server ที่เจ้าของดู รันจากโฟลเดอร์ไหน → แก้โฟลเดอร์นั้น + ตรวจ Header/Footer/Element ว่าเป็นโปรเจกต์ที่จองจริง (กันแก้ผิดโปรเจกต์)
- ประกาศสถานี: [Migrate เฟส 8/13 · สถานี M4 · เมนู: <ชื่อ> · โปรเจกต์: <ชื่อ>]

[เนื้องาน]
M4-1 อ้าง Design System เท่านั้น (token ตาม ds_version ใน profile) ห้ามคิดสี/ฟอนต์ใหม่กลางทาง ·
     กฎสีลำดับชั้น 60/30/10: พื้น ~60 · สีรอง ~30 · สีหลักเฉพาะจุดเน้น ~10 · ขาดเฉด/ฟอนต์ = ต้องอนุมัติแล้วจากเฟส 7 เท่านั้น
M4-2 ห้ามยืม component ที่ฝังภาพ/asset ของเว็บอื่น (บทเรียนภาพ DRA หลุดไปโผล่เว็บ กปถ.)
M4-3 ชั้นการเห็นงาน 3 ชั้น: ทำบนเครื่องทำงาน → เจ้าของดูผ่านลิงก์กดเปิดได้จริง (ห้ามส่ง localhost) → อนุมัติ → ค่อยขึ้น dev ให้ทีมเห็น
M4-4 เจอ pattern/component ใหม่ระหว่างทำ → จดเตรียมเสนอเข้า DS (ไปบันทึกที่เฟส 13) ห้ามเอาไปใช้ก่อนอนุมัติ
M4-5 กฎ Mock Data: ยังไม่มีข้อมูลจริง ใช้ตัวอย่างได้ แต่ติดป้าย "ข้อมูลตัวอย่าง (Mock)" สีเตือน + จดลงบัตรเมนู — ห้ามปล่อยหน้า mock เนียนเป็นของจริง

14 pattern กลาง — ทุกตัวที่หน้านี้ใช้ ต้องทำครบ 6 ช่อง (หน้าตา/พฤติกรรม/ข้อมูล/สถานะผิดปกติ/การเข้าถึง/หลักฐานทดสอบ):
footer · hero-listing · quicklink · การ์ดข่าว · collapse-รายการไฟล์ · lightbox+ปุ่มดาวน์โหลด · filter/date-picker · breadcrumb ·
ไอคอน+ข้อความกำกับ · แถวไฟล์ดาวน์โหลด (ปุ่มโหลด+แจ้งไฟล์เสีย+tag ชนิด) · แท็บ/in-page-nav/sticky (คีย์บอร์ด+ลิงก์ตรง+ไม่บัง) ·
pagination (บังคับทุกหน้า list) · ชุดสถานะ loading/ว่าง/error/ไม่มีสิทธิ์ (ทุก section) · related-content+hashtag (ตำแหน่งเดียวทั้งเว็บ + ไม่ซ้ำหน้าปัจจุบัน)
กติกาความเป็นเนื้อเดียว: hover/pagination/ปุ่ม display (List/Thumbnail/Grid)/ปุ่มไลค์-แชร์ ตำแหน่งและพฤติกรรมเดียวกันทั้งโปรเจกต์ ·
magazine layout: อ่านซ้าย→ขวา บน→ล่าง · หน้ายาว >2 A4 มีภาพคั่นทุกช่วง A4 (ตามแผน brief) ·
ข้อมูลยาว = แท็บตามที่เจ้าของเคาะ + script ดึงแท็บติดบนจอ (คีย์บอร์ด/โฟกัส/ลิงก์ตรง/ไม่บังเนื้อหา) ·
hardcode = ข้อยกเว้นที่เจ้าของอนุมัติรายกรณีเท่านั้น (จดลงบัตรเมนูพร้อมเหตุผล)

[ส่วน 4 · ชุดคำถามบังคับ — จุดเดียว: ชั้นที่ 2 ของการเห็นงาน]
สร้างครบแล้ว → ส่งลิงก์กดเปิดได้จริงให้เจ้าของดู + แถบบอกสถานี + สรุป pattern ที่ใช้ →
รอเจ้าของตอบ "ผ่าน/แก้" ก่อนขึ้น dev ทีม · เจ้าของสั่งแก้ = แก้แล้วส่งดูใหม่ วนจนผ่าน ·
เจ้าของตอบผ่าน = จดป้าย `PHASE8_APPROVED` + ชื่อ + วันที่ + ลิงก์ที่ดู ลง .work/menu-cards/<เมนู>.approvals.md

[ส่วน 5 · ตารางจบเฟส]
(ก) ของส่งมอบ: ไฟล์หน้า (path จริงใน repo โปรเจกต์) + เช็กลิสต์ 14 pattern (ใช้กี่ตัว ครบ 6 ช่องกี่ตัว — เลขจากการไล่จริง) + บันทึกลิงก์ที่ส่งเจ้าของ + คำตอบเจ้าของ
(ข) ตาราง comply M4-1..M4-5 + pattern ที่ใช้ (N ตัว × 6 ช่อง = ตัวเลขจริง) + หลักฐาน
(ค) เลขจากเครื่อง: ds-check (token ตรง DS) + mw-page-check ถ้ามี — แปะผลรันจริง · ไม่มี = ระบุ "เครื่องยังไม่คุม"
ปิดท้าย: จบเฟส 8 — รอพี่ตรวจ · ถ้าผ่าน พิมพ์ `Use Migrate 9` · ผมเดินต่อเองไม่ได้ (กุญแจอยู่ที่พี่)

[ข้อห้ามเฉพาะเฟสนี้]
- ห้ามฝังเนื้อหาตายในโค้ด (hardcode เนื้อ) — เนื้อหาต้องเตรียมเข้าหลังบ้านที่เฟส 9 · ฝังตาย = ซ้ำรอย M5 5% ที่พี่เจ็บมาแล้ว
- ห้ามใช้ token/สีที่ไม่ได้อนุมัติ · ห้ามข้ามไปทดสอบหลังบ้าน (เฟส 9) หรือรันด่านมาตรฐาน (เฟส 10) เอง
```
