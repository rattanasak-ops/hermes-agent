# Use Migrate 9 — Admin คุมหน้าได้จริง (สถานี M5 · ด่านตาย)

> จุดที่เคยพังหนักสุด (5% · เนื้อ hardcode ไม่ต่อหลังบ้าน) · เฟสนี้มีด่านตายด้วยเครื่อง: ไม่พิสูจน์วงจรหลังบ้าน = ไม่ผ่าน เด็ดขาด

## Prompt

```text
Use Migrate 9

อ่านสัญญากลาง use-migrate-phase-contract.md ก่อน แล้วทำตามโครง 5 ส่วน

[ส่วน 1 · ด่านเข้า — รันจริง แปะผล]
1. .work/profile.yaml มีจริง — ไม่มี = MIGRATE_BLOCKED: ต้องทำ Use Migrate 0 ก่อน
2. ล็อกเมนูยังเป็นชื่อเรา + เฟส 8 ปิดจริง: `grep PHASE8_APPROVED .work/menu-cards/<เมนู>.approvals.md` ต้องเจอ (แปะผล) — ไม่เจอ = BLOCKED กลับเฟส 8 · คำพูดว่า "เจ้าของผ่านแล้ว" ไม่ใช่หลักฐาน
- ประกาศสถานี: [Migrate เฟส 9/13 · สถานี M5 · เมนู: <ชื่อ> · โปรเจกต์: <ชื่อ>]

[ก่อนออกแบบหน้าแก้ไข — ถามเจ้าของก่อน (ชุดคำถามบังคับที่ 1)]
- เช็กสิ่งที่ Root Admin สร้างให้เทียบ TOR/มาตรฐาน: field form ไหนจำเป็น field ไหนรก
- เสนอรายการ "field ที่ควรปิด/ซ่อน (ผ่าน config)" ให้เจ้าของเคาะรายข้อ — เน้นตรง TOR + การใช้จริง

[เนื้องาน]
M5-1 เนื้อหาเข้าโมดูล admin (cms/pages/document) ไม่ hardcode ในโค้ด
M5-2 เนื้อหาไหลออกหน้าเว็บผ่าน API (data-driven)
M5-3 พิสูจน์ CRUD: เพิ่ม→เด้งหน้าเว็บ / แก้→เปลี่ยน / ลบ→หาย (ภาพเป็นหลักฐาน · เช็คเนื้อหน้าจริง)
M5-4 บังคับ (DEC-160): ปิดได้เมื่อพิสูจน์ผ่านหน้าจอ Admin จริง (login→เมนู→สร้าง/แก้/ลบ→หน้าเว็บเปลี่ยน) + ภาพ
M5-5 ห้ามเคลม "แก้ผ่าน admin ได้" จากยิง API/curl — API ผ่าน = แค่หลังระบบ ไม่ใช่หลักฐานจอ
M5-6 WYSIWYG + Preview: แก้แล้วเห็นหน้าเหมือนจริง + ดูก่อนเผยแพร่ · (โน้ต: editor ปัจจุบัน TipTap ยังไม่ WYSIWYG เต็ม — ถ้าโปรเจกต์เปลี่ยน editor เตือนเจ้าของอัปเดต Flow ข้อนี้)
M5-7 กฎนี้เป็นด่านมาตรฐานทุกโปรเจกต์ (ยกเข้า Root Admin factory)

แทร็กเสริม (ทำเมื่อ profile เปิดไว้):
- FORM: พิสูจน์วงจรเต็ม กรอก→DB→หลังบ้านเห็น→ตอบกลับ/ติดตามสถานะ + PDPA (สิทธิ์ดู/อายุเก็บ/log เข้าถึง)
- BILINGUAL: CRUD ครบทั้ง 2 ภาษา
- เมนูมีไฟล์แนบ: ทดสอบวงจรปุ่มแจ้งไฟล์เสีย → เข้าหลังบ้านรวมปัญหา (ถ้า Module ยังไม่มี = เมนูนี้ปิดเกตไม่ได้ ตามที่จดไว้ตอนเปิดโปรเจกต์)

[ด่านตาย — เครื่องตัดสิน ไม่ใช่ปาก AI]
1. รัน mw-backend-check พิสูจน์วงจรจริง (กรอก→DB→เทียบค่า) — แปะผลเต็ม
2. ตรวจว่าโค้ดหน้าไม่มีเนื้อหาฝังตาย (grep เนื้อจริงในไฟล์หน้า ต้องไม่เจอก้อนเนื้อหา) — แปะผล
3. ภาพหน้าจอ admin จริงครบวงจร CRUD
ตกข้อใด = เฟสไม่ผ่าน ห้ามเข้าเฟส 10 เด็ดขาด · **ไม่มี mw-backend-check บนเครื่อง = `BLOCKED_TOOLING` เฟสนี้จบไม่ได้** — ไม่มีทางลัด "ภาพ+grep แทนเครื่อง" (กฎเหล็ก R-3: grep/คำพูดไม่ใช่หลักฐาน) · ทางออกเดียว: ติดตั้งชุดเครื่องมือทีม (`install-from-github.sh`) แล้วรันจริง — นี่คือด่านที่ตั้งใจกันเหตุ hardcode 5% ห้ามมีข้อยกเว้น

[ส่วน 4 · ชุดคำถามบังคับที่ 2 — จุดตรวจของเจ้าของ (Owner Checkpoint)]
ส่งภาพวงจร admin จริง + ผลด่านตาย แล้วให้เจ้าของทดสอบแก้เนื้อหาเอง 1 จุดผ่านจอ admin — เจ้าของยืนยัน = จดป้าย `PHASE9_APPROVED` + ชื่อ + วันที่ + สิ่งที่ดู ลง `.work/menu-cards/<เมนู>.approvals.md`

[ส่วน 5 · ตารางจบเฟส]
(ก) ของส่งมอบ: ผล mw-backend-check + ภาพจอ admin ครบวงจร + รายการ field ที่เคาะปิด + บันทึก manual_verified ของเจ้าของ
(ข) ตาราง comply M5-1..M5-7 + ด่านตาย 3 ข้อ + แทร็กเสริมที่เปิด = ครบทุกแถว + หลักฐาน
(ค) เลขจากเครื่อง: mw-backend-check (บังคับถ้ามี) + flow_gate.py · ไม่มี = ระบุ "เครื่องยังไม่คุม"
ปิดท้าย: จบเฟส 9 — รอพี่ตรวจ · ถ้าผ่าน พิมพ์ `Use Migrate 10` · ผมเดินต่อเองไม่ได้ (กุญแจอยู่ที่พี่)

[ข้อห้ามเฉพาะเฟสนี้]
- ห้ามรันด่านมาตรฐาน 9 เกต (เฟส 10) เอง · ห้ามสรุปว่า "หลังบ้านใช้ได้" โดยไม่มีภาพจอ + ผลเครื่อง
```
