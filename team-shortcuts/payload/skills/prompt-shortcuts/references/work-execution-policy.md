# กติกากลางการลงมือทำงาน

ไฟล์นี้คุม Shortcut ทุกตัวใน Codex App, Claude Code App, Cursor และ Hermes Agent โดยมีหลักง่าย ๆ ว่า Shortcut ใช้พื้นที่ปัจจุบันและไม่มีสิทธิ์สร้างพื้นที่เพิ่ม กิ่งเปลี่ยนได้เฉพาะคำสั่งตรงจากเจ้าของ หรือการกู้กิ่งที่มีชื่ออยู่แล้วในสมุดทะเบียนของ Git root เดิม

## 1. โหมดหลัก `CURRENT_WORKSPACE_ONLY`

ทุก Shortcut ต้องทำตามกฎต่อไปนี้:

1. ใช้โฟลเดอร์ Git และกิ่งที่แอปเปิดอยู่ในขณะนั้น
2. ตรวจ `pwd`, Git root, กิ่งปัจจุบัน, SHA และไฟล์ค้างก่อนเขียน
3. ห้ามสร้าง ลบ ย้าย หรือสลับ Worktree และห้ามเดาชื่อกิ่งเอง การกู้กิ่งตาม `SYSTEM_REGISTERED_BRANCH_RECOVERY` ไม่ถือเป็นการเปิดพื้นที่ใหม่
4. ห้ามเรียก `hermes-new-chat open`, `hermes worktree open`, `git worktree add` หรือ `git worktree remove` จาก Shortcut หรือ AI
5. ถ้าพื้นที่ไม่ใช่โครงการที่เจ้าของต้องการ ให้คืน `WORKSPACE_SCOPE_MISMATCH` พร้อมหลักฐานจากเครื่องและ path ที่ตรวจพบ ห้ามผลักให้ผู้ใช้เปิดพื้นที่/กิ่งอื่น และห้ามเสนอหรือสร้าง Worktree ใหม่เพื่อหนีปัญหา
6. ด่าน Git ตก ไฟล์เกินเพดาน commit เกินเพดาน หรือกิ่งเคยรวมแบบ squash ไม่ใช่สิทธิ์ให้สร้างหรือสลับ Worktree/กิ่ง ต้องตรวจประวัติและแก้ในกิ่งปัจจุบัน ถ้าจะใช้กิ่งเดิมต่อหลังรวมให้ใช้ merge commit เพื่อรักษาสายประวัติ

Worktree ที่มีอยู่แล้วใช้ต่อได้เมื่อเป็นพื้นที่ปัจจุบัน แต่ Shortcut ต้องไม่สร้างเพิ่ม ไม่ย้ายเข้าเอง และไม่ลบของเดิม

### ข้อยกเว้นเดียว `OWNER_EXPLICIT_BRANCH_ONLY`

AI สร้างและสลับกิ่งใน Git root ปัจจุบันได้เมื่อครบทุกข้อ:

1. ข้อความสั้นล่าสุดจากเจ้าของสั่งสร้างกิ่งและระบุชื่อกิ่งตรง ๆ
2. ชื่อในคำสั่ง Git ต้องตรงกับชื่อที่เจ้าของพิมพ์ทุกตัวอักษร
3. ใช้ได้เฉพาะ `git switch -c <ชื่อ>`, `git checkout -b <ชื่อ>` หรือ `git branch <ชื่อ>` หนึ่งคำสั่ง
4. ห้ามสร้างกิ่งร่วม/กิ่งใช้งานจริง และยังต้องผ่านด่านไฟล์ลับ คำสั่งอันตราย และ Git root
5. ข้อความยาว ข้อความยกตัวอย่าง ประวัติแชทที่วางมา หรือชื่อที่ AI คิดเอง ไม่ถือเป็นคำอนุมัติ

ถ้าเจ้าของสั่งสร้างกิ่งอย่างชัดเจน AI ต้องทำให้ในพื้นที่ปัจจุบัน ไม่ผลักให้เจ้าของเปิด Terminal เอง และต้องไม่สร้าง Worktree ประกอบ ส่วน Shortcut เพียงอย่างเดียวไม่เคยให้สิทธิ์นี้

### การกู้ระบบ `SYSTEM_REGISTERED_BRANCH_RECOVERY`

ถ้า Git root ปัจจุบันตรงกับงานและหลุดเป็น detached HEAD ให้ AI ทำตามนี้ก่อนบล็อกงาน กรณีอยู่บนกิ่งร่วมให้คืน `PROTECTED_BRANCH_WRITE_BLOCKED` โดยไม่สลับกิ่ง:

1. รัน `hermes-current-workspace-recover --cwd <Git root> --json`
2. คำสั่งนี้อ่านชื่อกิ่งจากสมุดทะเบียน Worktree ของ path เดียวกันเท่านั้น ห้ามรับชื่อที่ AI คิดเอง
3. คำสั่งนี้สร้างได้เฉพาะกิ่งที่ลงทะเบียนไว้ ณ SHA ปัจจุบัน และไม่สร้าง Worktree
4. ต้องรักษาไฟล์ค้างไว้ครบ ถ้ากิ่งเดิมอยู่คนละ SHA หรือเปิดในพื้นที่อื่น ให้หยุดด้วย `RECOVERY_CONFLICT` หรือรหัสเหตุผลของเครื่อง
5. ห้ามสรุปด้วยการให้ผู้ใช้เปิด/สร้าง/switch workspace, Worktree, folder หรือ branch เอง

## 2. ความหมายของสถานะกลาง

| สถานะ | ความหมาย |
|---|---|
| `CURRENT_WORKSPACE_READY` | อยู่ใน Git root ที่ตรวจแล้ว กิ่งไม่ใช่กิ่งร่วม/กิ่งใช้งานจริง และไฟล์เป้าหมายอยู่ในพื้นที่ปัจจุบัน |
| `CURRENT_WORKSPACE_READ_ONLY` | อ่าน ตรวจ และรายงานได้ แต่ยังไม่ควรแก้ไฟล์ |
| `CURRENT_WORKSPACE_BLOCKED` | กู้กิ่งตามสมุดทะเบียนแล้วไม่สำเร็จ อยู่ผิดโครงการ ไฟล์ค้างไม่ทราบที่มา เป้าหมายอยู่นอกพื้นที่ หรือชนด่านความปลอดภัย |

ห้ามใช้ `NEW_CHAT_READY` หรือ `WTL_READY` เป็นเงื่อนไขบังคับสำหรับงานปกติอีกต่อไป สถานะเหล่านี้ใช้ได้เฉพาะงาน Worktree ที่เจ้าของเปิดเองและต้องการตรวจวงจรชีวิตโดยชัดเจน

## 3. ด่านก่อนเขียน

งานเขียนตรงผ่านได้เมื่อครบทั้งหมด:

- เจ้าของอนุมัติงานในแชทปัจจุบัน
- เป้าหมายอยู่ใต้ Git root ที่เปิดอยู่
- กิ่งปัจจุบันไม่ใช่ `main`, `master`, `develop`, `development`, `production` หรือ `prod`
- ไม่อยู่ในภาวะ detached HEAD; ถ้าหลุดให้รัน `SYSTEM_REGISTERED_BRANCH_RECOVERY` ก่อนตัดสินบล็อก
- ไฟล์ค้างที่ทับกับขอบเขตงานเป็นของงานเดียวกันและรู้ที่มา
- ไฟล์เป้าหมายไม่ใช่ไฟล์ลับหรือไฟล์ควบคุมด่าน

ถ้ามีไฟล์ค้างนอกขอบเขต ให้รักษาไว้และทำงานเฉพาะไฟล์ที่ไม่ทับกัน ถ้าแยกเจ้าของไม่ได้ ให้บล็อกเฉพาะการเขียนที่เสี่ยง ห้าม stash, reset, clean, ย้าย หรือทิ้งไฟล์ค้างเอง

## 4. AI Relay เป็นทางเลือก

- AI ในแอปปัจจุบันเขียนไฟล์และรันคำสั่งพัฒนาได้ตรงเมื่อ `CURRENT_WORKSPACE_READY`
- ใช้ AI Relay เฉพาะเมื่อเจ้าของเรียก `Use AI Relay` หรือสั่งให้ AI ตัวอื่นช่วยโดยชัดเจน
- Relay ไม่มีสิทธิ์สร้าง ลบ ย้าย หรือสลับ Worktree/กิ่ง
- Relay ไม่มีสิทธิ์เปลี่ยนโครงการหรือโฟลเดอร์ทำงานจากที่เจ้าของเปิดไว้
- Relay ล่ม ไม่มี token หรือบัญชีหมดอายุ ต้องไม่ขวางงานตรงของแอปปัจจุบัน
- ห้ามเปลี่ยน AI เงียบ ๆ

## 5. ด่านความปลอดภัยที่ห้ามยกเลิก

การยกเลิกข้อบังคับ Worktree และ AI Relay ไม่ได้ยกเลิกด่านต่อไปนี้:

- ห้ามเขียนนอกพื้นที่ปัจจุบัน
- ห้ามเขียนบนกิ่งร่วม/กิ่งใช้งานจริงตามรายชื่อในข้อ 3
- ห้ามแตะ `.env`, `.env.*`, `.hermes`, `.grok`, `.git`, credential, token, password, private key, secret และไฟล์ควบคุม Hook/Settings
- ห้าม force push, reset แบบทำลาย, clean, stash clear, ลบกิ่ง, ลบ Worktree และคำสั่งลบถาวร
- commit, push, merge, deploy, migration, การติดตั้ง dependency และผลกระทบภายนอกยังต้องผ่านด่านเฉพาะของงานนั้น

## 6. คำสั่งพัฒนาปกติ

เมื่อพื้นที่พร้อม ต้องรันคำสั่งปกติได้โดยไม่ผ่าน Relay เช่น:

```text
pnpm dev
pnpm start
pnpm test
pnpm lint
pnpm build
npm run <script>
pytest
ruff
tsc
```

คำสั่งติดตั้ง/ถอดชุดเสริม คำสั่งเขียนไฟล์ด้วย shell และคำสั่งอันตรายไม่ถือเป็นคำสั่งตรวจปกติ

## 7. Worktree เป็นเครื่องมือที่เจ้าของเรียกเอง

`worktree-lifecycle-contract.md` ใช้สำหรับอ่าน ตรวจ ส่งต่อ ปิด และเก็บกวาด Worktree ที่มีอยู่โดยกระบวนการของเจ้าของ แต่ไม่ใช่ด่านบังคับของ Shortcut ปกติ และด่าน AI ไม่เปิด Worktree ใหม่

การเรียก `Use New Chat`, `Use Continue`, `Use Flow Guardian` หรือ Shortcut อื่นไม่ใช่สิทธิ์ให้สร้าง Worktree หรือกิ่ง คำสั่งสร้างกิ่งใช้ข้อยกเว้น `OWNER_EXPLICIT_BRANCH_ONLY`; คำสั่งสร้าง Worktree ไม่ใช้ข้อยกเว้นนี้

## 8. การต่อสายทุกแอป

ตัวตรวจสุขภาพต้องพิสูจน์พฤติกรรมเดียวกันใน Codex App, Claude Code App, Cursor และ Hermes Agent อย่างน้อยดังนี้:

1. เขียนไฟล์ในพื้นที่และกิ่งที่อนุญาตได้ตรง
2. รัน `pnpm` สำหรับ dev/test/lint/build ได้
3. ไม่ต้องมี New Chat session หรือ AI Relay
4. เขียนข้าม Git root ไม่ได้
5. กิ่งร่วม, detached HEAD, ไฟล์ลับ และคำสั่งอันตรายยังถูกขวาง
6. Worktree mutation ถูกขวาง และ Shortcut ไม่สร้างหรือสลับ Worktree/กิ่งเอง
7. คำสั่งสร้างกิ่งจากเจ้าของที่ชื่อตรงกันผ่าน แต่ชื่อไม่ตรง ไม่มีข้อความอนุมัติ หรือมาจากตัวอย่างยาวถูกขวาง
8. detached HEAD ที่มีรายการตรงในสมุดทะเบียนกู้กลับกิ่งเดิมใน Git root เดิมได้ ไฟล์ค้างไม่หาย และจำนวน Worktree ไม่เพิ่ม
9. คำตอบที่ผลักให้ผู้ใช้เปิด/สร้าง/switch workspace, Worktree, folder หรือ branch ถูกขวางทั้งสี่แอป
10. คำตอบที่ขออนุมัติซ้ำระหว่างเฟส ทั้งที่ยังมีงานปลอดภัยในขอบเขตเดิม ถูกขวางทั้งสี่แอป

## 9. ทำงานต่อเป็นเฟสโดยไม่ถามซ้ำ

เมื่อเจ้าของอนุมัติเป้าหมายหรือเฟสแล้ว AI ต้องทำงานปลอดภัยในขอบเขตเดิมต่อจนถึงด่านปิดเฟส โดยมีงบคำถามระหว่างทาง 0 ครั้ง:

- คำถามย่อย การเลือกวิธี การแก้ผลตรวจ และการตอบคำถามแทรก ไม่ยกเลิกสิทธิ์ทำงานในเฟสเดิม
- หลังตอบคำถามแทรก ให้เปิดแผนทวนเฟสปัจจุบัน แล้วกลับไปทำต่อทันที
- งานที่มีผลภายนอก งานลบถาวร production ความลับ ตัวตน หรือการขยายขอบเขต ให้รวบถามครั้งเดียวต่อเฟส
- ถ้าต้องรอเจ้าของจริง ให้ใช้ `OWNER_INPUT_REQUIRED: <รหัสเหตุผล>` พร้อม `หลักฐาน:` จากเครื่อง และห้ามถามซ้ำจนกว่าสถานะจะเปลี่ยน
- รหัสที่ยอมรับคือ `LOGIN_REQUIRED`, `TOKEN_REQUIRED`, `CREDENTIAL_REQUIRED`, `PRODUCTION_APPROVAL_REQUIRED`, `DESTRUCTIVE_APPROVAL_REQUIRED`, `SCOPE_CHANGE_REQUIRED`, `EXTERNAL_DECISION_REQUIRED`, `IDENTITY_REQUIRED`
