# กติกากลางการลงมือทำงาน

ไฟล์นี้คุม Shortcut ทุกตัวใน Codex App, Claude Code App, Cursor และ Hermes Agent โดยมีหลักง่าย ๆ ว่า เจ้าของเป็นคนเปิดโครงการและกิ่งที่จะทำงาน ส่วน Shortcut มีหน้าที่ตรวจและทำงานในพื้นที่ที่เปิดอยู่เท่านั้น

## 1. โหมดหลัก `CURRENT_WORKSPACE_ONLY`

ทุก Shortcut ต้องทำตามกฎต่อไปนี้:

1. ใช้โฟลเดอร์ Git และกิ่งที่แอปเปิดอยู่ในขณะนั้น
2. ตรวจ `pwd`, Git root, กิ่งปัจจุบัน, SHA และไฟล์ค้างก่อนเขียน
3. ห้ามสร้าง ลบ ย้าย หรือสลับ Worktree และกิ่งโดยอัตโนมัติ
4. ห้ามเรียก `hermes-new-chat open`, `hermes worktree open`, `git worktree add`, `git worktree remove`, `git switch`, `git checkout` หรือคำสั่งสร้าง/สลับกิ่งจาก Shortcut
5. ถ้าพื้นที่หรือกิ่งไม่เหมาะกับงาน ให้คืน `CURRENT_WORKSPACE_BLOCKED` พร้อมบอกการกระทำเดียวที่เจ้าของต้องทำ ห้ามสร้างพื้นที่ใหม่เพื่อหนีปัญหา

Worktree ที่มีอยู่แล้วใช้ต่อได้เมื่อเป็นพื้นที่ปัจจุบัน แต่ Shortcut ต้องไม่สร้างเพิ่ม ไม่ย้ายเข้าเอง และไม่ลบของเดิม

## 2. ความหมายของสถานะกลาง

| สถานะ | ความหมาย |
|---|---|
| `CURRENT_WORKSPACE_READY` | อยู่ใน Git root ที่ตรวจแล้ว กิ่งไม่ใช่กิ่งร่วม/กิ่งใช้งานจริง และไฟล์เป้าหมายอยู่ในพื้นที่ปัจจุบัน |
| `CURRENT_WORKSPACE_READ_ONLY` | อ่าน ตรวจ และรายงานได้ แต่ยังไม่ควรแก้ไฟล์ |
| `CURRENT_WORKSPACE_BLOCKED` | กิ่งผิด อยู่ผิดโฟลเดอร์ ไฟล์ค้างไม่ทราบเจ้าของ เป้าหมายอยู่นอกพื้นที่ หรือชนด่านความปลอดภัย |

ห้ามใช้ `NEW_CHAT_READY` หรือ `WTL_READY` เป็นเงื่อนไขบังคับสำหรับงานปกติอีกต่อไป สถานะเหล่านี้ใช้ได้เฉพาะงาน Worktree ที่เจ้าของเปิดเองและต้องการตรวจวงจรชีวิตโดยชัดเจน

## 3. ด่านก่อนเขียน

งานเขียนตรงผ่านได้เมื่อครบทั้งหมด:

- เจ้าของอนุมัติงานในแชทปัจจุบัน
- เป้าหมายอยู่ใต้ Git root ที่เปิดอยู่
- กิ่งปัจจุบันไม่ใช่ `main`, `master`, `develop`, `development`, `production` หรือ `prod`
- ไม่อยู่ในภาวะ detached HEAD
- ไฟล์ค้างที่ทับกับขอบเขตงานเป็นของงานเดียวกันและรู้ที่มา
- ไฟล์เป้าหมายไม่ใช่ไฟล์ลับหรือไฟล์ควบคุมด่าน

ถ้ามีไฟล์ค้างนอกขอบเขต ให้รักษาไว้และทำงานเฉพาะไฟล์ที่ไม่ทับกัน ถ้าแยกเจ้าของไม่ได้ ให้บล็อกเฉพาะการเขียนที่เสี่ยง ห้าม stash, reset, clean, ย้าย หรือทิ้งไฟล์ค้างเอง

## 4. AI Relay เป็นทางเลือก

- AI ในแอปปัจจุบันเขียนไฟล์และรันคำสั่งพัฒนาได้ตรงเมื่อ `CURRENT_WORKSPACE_READY`
- ใช้ AI Relay เฉพาะเมื่อเจ้าของเรียก `Use AI Relay` หรือสั่งให้ AI ตัวอื่นช่วยโดยชัดเจน
- Relay ไม่มีสิทธิ์สร้าง ลบ ย้าย หรือสลับ Worktree/กิ่ง
- Relay ไม่มีสิทธิ์เปลี่ยนโครงการหรือโฟลเดอร์ทำงานจากที่เจ้าของเปิดไว้
- Relay ล่ม ไม่มี token หรือบัญชีหมดอายุ ต้องไม่ขวางงานตรงของแอปปัจจุบัน
- ห้ามเปลี่ยน AI เงียบ ๆ

## 5. ด่านความปลอดภัยที่ห้ามยกเลิก

การยกเลิกข้อบังคับ Worktree และ AI Relay ไม่ได้ยกเลิกด่านต่อไปนี้:

- ห้ามเขียนนอกพื้นที่ปัจจุบัน
- ห้ามเขียนบนกิ่งร่วม/กิ่งใช้งานจริงตามรายชื่อในข้อ 3
- ห้ามแตะ `.env`, `.env.*`, `.hermes`, `.grok`, `.git`, credential, token, password, private key, secret และไฟล์ควบคุม Hook/Settings
- ห้าม force push, reset แบบทำลาย, clean, stash clear, ลบกิ่ง, ลบ Worktree และคำสั่งลบถาวร
- commit, push, merge, deploy, migration, การติดตั้ง dependency และผลกระทบภายนอกยังต้องผ่านด่านเฉพาะของงานนั้น

## 6. คำสั่งพัฒนาปกติ

เมื่อพื้นที่พร้อม ต้องรันคำสั่งปกติได้โดยไม่ผ่าน Relay เช่น:

```text
pnpm dev
pnpm start
pnpm test
pnpm lint
pnpm build
npm run <script>
pytest
ruff
tsc
```

คำสั่งติดตั้ง/ถอดชุดเสริม คำสั่งเขียนไฟล์ด้วย shell และคำสั่งอันตรายไม่ถือเป็นคำสั่งตรวจปกติ

## 7. Worktree เป็นเครื่องมือที่เจ้าของเรียกเอง

`worktree-lifecycle-contract.md` ยังใช้สำหรับการตรวจ ส่งต่อ ปิด และเก็บกวาด Worktree ที่มีอยู่ หรือเมื่อเจ้าของสั่งสร้าง Worktree โดยตรง แต่ไม่ใช่ด่านบังคับของ Shortcut ปกติ

Shortcut จะเข้าสู่โหมด Worktree ได้ต่อเมื่อเจ้าของใช้คำสั่งตรงที่มีคำว่า Worktree และระบุงานชัดเจน การเรียก `Use New Chat`, `Use Continue`, `Use Flow Guardian` หรือ Shortcut อื่นเพียงอย่างเดียวไม่ใช่สิทธิ์ให้สร้าง Worktree/กิ่ง

## 8. การต่อสายทุกแอป

ตัวตรวจสุขภาพต้องพิสูจน์พฤติกรรมเดียวกันใน Codex App, Claude Code App, Cursor และ Hermes Agent อย่างน้อยดังนี้:

1. เขียนไฟล์ในพื้นที่และกิ่งที่อนุญาตได้ตรง
2. รัน `pnpm` สำหรับ dev/test/lint/build ได้
3. ไม่ต้องมี New Chat session หรือ AI Relay
4. เขียนข้าม Git root ไม่ได้
5. กิ่งร่วม, detached HEAD, ไฟล์ลับ และคำสั่งอันตรายยังถูกขวาง
6. Shortcut ไม่สร้างหรือสลับ Worktree/กิ่ง
